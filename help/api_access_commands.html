Allowed commands

Choose which commands this API account can run. The label beside each command names the module that provides it.

create-domain, clone-domain, disable-domain and enable-domain require Virtualmin Pro when used by an API account. They are disabled in this selector on GPL. Plan changes with modify-domain remain available under the account's permissions.

  • Allow selected commands: allow only the checked commands. An empty selection allows no commands.
  • Allow all current commands except selected: allow every available command except the checked ones. An empty selection allows all available commands.
  • Allow all current commands: allow every available command in the current list.

All three modes save the commands allowed when you click Save. Commands added later need permission before the account can use them. When you edit the account again, its allowed commands are checked under Allow selected commands.

Upgrading to Pro does not add commands to existing accounts automatically. Select the additional commands, or choose Allow all current commands, and save again.

After a downgrade, Pro command permissions stay saved, but those commands cannot run on GPL. Saving Allow all current commands or Allow all current commands except selected on GPL removes these inactive permissions.

Commands limited to allowed virtual servers

These commands check which virtual servers the account may manage. They also check template and plan permissions where needed. create-domain requires an allowed default template and plan.

Server-wide commands

These permissions can affect the whole server or grant root access, even when virtual servers, templates and plans are restricted. Allow them only for integrations you trust with this access.

The selection mode above applies to these commands too. Allow all current commands includes them.

If a different module takes over a command, this account loses access to it. Review the replacement before allowing it again. Updates within the same module keep the existing permission.

Entries marked Extra permission unlock specific options of modify-domain. They require that command to be allowed too and still check access to the target virtual server. modify-domain-quotas allows --quota and --uquota to override plan quotas. modify-domain-2fa allows --disable-2fa.

modify-domain-home allows --home, and modify-domain-hooks allows --pre-command and --post-command. These are server-wide permissions because paths and hooks use root privileges. They cannot be used through run-api-command. Extra permissions are not commands you can call directly. Existing grants do not gain them automatically. The selection modes apply to these entries too.

Some commands have more than one name. Allowing or blocking a command applies to all of its names. Each command still checks its own permissions.
